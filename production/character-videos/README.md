### Lite의 캐릭터 외형 유지

Lite는 `referenceImages`를 지원하지 않으며, `image`에 넣은 한 장을 시작
프레임으로 움직이게 합니다. 기존 정사각형 캐릭터 참조를 그대로 첫 프레임으로
넣지 않고, 게임 외형과 해당 장면의 배경을 담은 세로 시작 프레임을 먼저 준비해
검토합니다. 각 장면의 `startFrameImage`는
`starting-frames/<캐릭터ID>/opening.png`를 가리킵니다. 캐릭터당 하나의 시작 이미지를 네 장면에 재사용하며 서로 다른 장면별 동작을 요청합니다.

시작 이미지는 게임 외형과 핑구의 클레이 스타일을 참고해 built-in imagegen으로 준비합니다. Gemini 이미지 생성 API는 호출하지 않습니다. 사용한 프롬프트는 캐릭터별 `prompt.md`에 보관합니다. 1080×1920 PNG를 확인한 뒤 영상 생성을 시작하며, 준비되지 않은 경우 API 요청 전에 중단합니다.

## 실행

Node, 프로젝트 의존성, FFmpeg가 필요합니다. 서버 전용 키는 Git에서 제외된
`.env.local`의 `GEMINI_API_KEY`, `ELEVENLABS_API_KEY`에서 읽습니다.
FFmpeg가 PATH에 없으면 `FFMPEG_PATH`에 실행 파일 절대 경로를 지정합니다.

```sh
# 꼬미의 시작 이미지를 준비·검토한 후 실행
node --import tsx scripts/generate-portrait-videos.ts generate ggomi
node --import tsx scripts/generate-portrait-videos.ts build ggomi
# 네 장면의 외형·동작·마지막 인사와 더빙을 직접 확인한 뒤 실행
node --import tsx scripts/generate-portrait-videos.ts publish ggomi
```

`generate`는 현재 캐릭터의 네 장면을 하나씩 요청하며 첫 실패에서 중단합니다. 계정의 낮은 분당 한도를 고려해 `--parallel-scenes`는 API 호출 전에 차단합니다. `build`는 더빙을
캐시에서 가져오거나 포함 크레딧 안에서 생성한 뒤 길이를 맞추고 배경음을
덕킹하여 30초 결과를 만듭니다. `publish`는 규격과 체크섬, 원본 백업을
확인한 뒤 해당 캐릭터의 영상·포스터·캐시 버전을 교체합니다.

재생은 저장된 파일만 사용하며 생성 API를 호출하지 않습니다.

### 2026-10-14 제작 재개

재개 전에는 6명의 세로 영상과 음메 첫 장면이 저장되어 있었습니다. 음메의 나머지 세 장면을 생성하고 저장된 더빙으로 편집·검수·적용한 뒤 누룽지 네 장면을 완성했습니다. 준비된 한국어 더빙 8개를 재사용했으며 새 음성 합성은 하지 않았습니다. **당시 30초 기본편의 남은 생성 작업은 없었습니다.** 아래 명령은 제작 당시 순서이며, 완성된 영상에 `generate`를 다시 실행하면 공개 파일의 체크섬을 확인하고 유료 요청 없이 종료합니다.

```sh
node --import tsx scripts/generate-portrait-videos.ts generate nurungji
node --import tsx scripts/generate-portrait-videos.ts build nurungji
# 네 장면과 더빙을 검수한 뒤
node --import tsx scripts/generate-portrait-videos.ts publish nurungji
```

이번 재개에서 성공한 추가 생성은 총 7장면·56초로, Lite 1080p 초당 $0.08 기준 영상 예상 비용은 **$4.48**입니다. 정확한 청구 금액은 공급자 사용량 화면을 기준으로 합니다. 2026-10-09 배치의 성공한 Lite 11장면·88초·예상 $7.04와 당시 포함 크레딧으로 만든 585자·28개 더빙은 과거 제작 기록입니다. 자동 예약이나 자동 재시도는 설정하지 않았습니다.

라노 일부 장면에 귀·표정 변화가 있습니다. 유료 품질 재생성 없이 사용한다는 요청에 따라 유지했으며, 이후 장면에는 원래 해부 구조와 의상을 유지하도록 지시를 보강했습니다.

- 세로 MP4 8개·확장 완료 기록·manifest의 SHA-256, 30초 백업 8개와 기본편 기록, 가로 원본/백업 8쌍의 SHA-256이 모두 일치했습니다. 이전 포스터와 가로 MP4는 변경하지 않았습니다.
- 앱의 390×844 모바일에서 도치와 핑구가 새 38초 파일을 재생하고 끝나는 것을 확인했습니다. 핑구는 1024×768 태블릿·1440×900 PC 가로에서 기존 1280×720 영상으로 전환되고, 다시 세로에서 38초 파일로 돌아오며 위치를 유지했습니다. 다시 보기·홈 복귀·음소거 설정 유지와 브라우저 오류 없음도 확인했습니다. 실제 iPad 기기 검증은 아닙니다.
- 기본편 도구의 `generate`/`publish`를 완성된 도치에 실행해 38초 영상을 재생성하거나 30초로 덮어쓰지 않고 캐시 확인 후 종료함을 확인했습니다. 테스트 119개, `npm run lint`, `npm run build`를 통과했습니다.

## 8초 보너스 확장 도구

시작 이미지와 정확한 프롬프트는 `starting-frames/<캐릭터ID>/scene-5.png` 및 `scripts/generate-bonus-scenes.ts`의 `BONUS_SCENES`에 있습니다. 보너스만 8초 생성하며 기본 네 장면을 재생성하지 않습니다.

```sh
node --import tsx scripts/generate-bonus-scenes.ts generate dochi
# 이전 HTTP 429 등 명시적 거절 원인을 해결한 경우에만 --retry-rejected 추가
node --import tsx scripts/generate-bonus-scenes.ts build dochi
# 새 장면과 더빙을 직접 확인한 뒤
node --import tsx scripts/generate-bonus-scenes.ts publish dochi
```

- 기본편 도구도 공개된 38초 영상은 캐시로 인정하며 `publish`로 30초 파일을 덮어쓰지 않습니다.
- `generate`: 공유 `active.lock`으로 기본편 도구와 동시 실행을 막습니다. 저장된 작업 ID·완료 MP4를 재사용하며 불확실한 제출·실패한 작업은 자동으로 새 요청을 보내지 않습니다. 거절 재시도에는 동일한 입력과 명시적 옵션이 필요합니다. 이미 5장면이 공개되었다면 체크섬 확인 후 새 요청 없이 종료합니다.
- `build`: 원본 30초의 SHA-256을 완료 기록과 대조합니다. 기존 해상도를 유지해 결합하고, 저장된 음성에 캐릭터 피치·효과음 덕킹·리미터·끝 페이드를 적용합니다. 38초·24fps·해상도·전체 영상/음성 디코딩을 확인하고 `extended-validated.json`을 기록합니다.
- `publish`: 검증값과 현재 원본을 다시 확인하고, 변경 불가 원본 백업을 만든 뒤 MP4·manifest·확장 완료 기록을 갱신합니다. 기존 30초 백업에 38초 결과를 덮어쓰거나 같은 보너스를 반복해서 붙이지 않습니다. 기존 포스터를 유지합니다.
- 로컬 `.video-generation/portrait-v1/<캐릭터ID>/scene-5.json/.mp4`, `extended-final.mp4`, `extended-validated.json`을 삭제하지 않습니다. 새 환경에서 다시 생성하기 전에 이 기록을 복구해야 합니다.
- 강제 종료 후 남은 잠금은 기록된 프로세스가 종료되었는지 확인하고 복구합니다. 아래 기본편의 `--recover-lock` 옵션은 보너스 도구에는 없습니다.

## 저장과 재개

`.video-generation/portrait-v1/<캐릭터ID>/`는 Git에서 제외되며 다음을 보관합니다.

- `scene-N.json`: 요청 입력 해시, 모델, 작업 ID, 진행 상태
- `scene-N.mp4`: 다운받은 원본 장면(신규 Lite 1080p, 기존 핑구 4K)
- `dubs/`: 원본 음성, 합성 요청 기록, 캐릭터 피치를 적용한 WAV
- `final.mp4`, `poster.jpg`, `validated.json`: 편집 결과와 검증값

통신 중단 후 같은 `generate` 명령을 실행하면 저장된 작업 ID를 조회합니다.
완성된 파일은 재사용하며 자동 유료 재생성은 하지 않습니다. HTTP 402 등
명시적인 요청 거절은 원인을 해결한 뒤 승인된 제작 범위 안에서만
`--retry-rejected`를 붙여 재개합니다. 이 옵션은 유료 품질 재생성 승인을
대신하지 않습니다.
작업 ID가 오기 전에 연결이 끊긴 불확실한 요청은 중복 과금을 막기 위해
중단합니다. API에서 결과를 먼저 확인하고 기록을 복구해야 합니다.
`active.lock`이 남았다면 `--recover-lock`을 붙여 실행합니다. 기록된 PID가
종료된 경우에만 잠금을 해제하며 실행 중인 프로세스의 잠금은 유지합니다.

## 검수

스크립트는 장면 계획에 맞는 해상도(신규 1080×1920, 기존 핑구 2160×3840),
24fps, 장면 8초/기본편 30초·확장편 38초를 검사합니다. 더빙은
원문을 자르지 않고 자연스러운 범위의 템포만 조정하며 각 장면에 맞는 길이를
확인합니다. 최종 영상의 실제 외형, 오디오, 장면 경계와 모바일 재생은 직접
검토합니다. 기존 짧은 영상을 반복·확대하는 도구와 이전 가로 생성 도구는 정리했습니다. 기본편 제작 진입점은 `generate-portrait-videos.ts`, 보너스 확장은 `generate-bonus-scenes.ts`입니다.
